# Resident 2026 — UX v2: цифровой помощник очной кампании

> Основа: одна общая очная кампания, игроки с телефонами Android, мастер с планшета. Не виртуальный игровой стол. Правила Resident 2026 — авторская облегчённая версия WoD; правила в архиве приоритетнее любых других систем.

## Что сейчас не работает

- Cloudflare PWA `cloudflare/resident-paper-worker.js` — самостоятельный локальный чарник (`localStorage`), мастер его не видит, эффект назначить не может.
- В `server/index.js` уже есть аккаунты, роли, одна кампания, серверные чарники, журнал и SSE; это **отдельный** продукт, не подключённый к PWA.
- Псевдографика и многоступенчатое досье мешают игре, потому что главное действие — бросок/состояние/вещь — глубоко ниже первого экрана.
- Изображения и стили не заменяют удобные рабочие сценарии.

Решение: **не форкать целиком VTT или D&D-приложение**. Сначала соединить существующий сервер и мобильный UI. Рабочие процессы, подходы к компонентам и архитектура — ориентиры. Для прямого переиспользования кода проверять лицензии каждого компонента.

## Первый экран игрока — режим «Игра»

Всё необходимое для текущей сцены видно без прокрутки или одним касанием:

1. Имя/позывной и **текущее здоровье физическое + психическое**.
2. Активные эффекты (максимум 2 кратких бейджа, остальные по тапу). Отсутствие эффекта не занимает место.
3. **Проверка** — атрибут → навык → бросить d10, без браузерных `prompt`. Сложность/модификатор задаёт мастер по правилам.
4. Быстрые «Ранение», «Использовать вещь», «Заметка» с контролируемыми правами.
5. Изображение досье, код сотрудника, отпечатки и биография живут **только во вкладке «Досье»**.

Нижние вкладки (максимум 4): **Игра / Навыки / Вещи / Досье**. Здоровье подробно открывается с карточки на главном экране. «Настройка/Создание» — отдельный режим, не смешивать с игрой.

Не менять цифры с каждым нажатием при просмотре: **Просмотр** по умолчанию, редактирование только после явного «Изменить». Сохранение немедленное; ошибка синхронизации заметна и не затирает локальный черновик.

## Планшет мастера — «Пульт»

Альбомная ориентация: слева **группа** (персонажи, здоровье, состояния, быстрый поиск), справа **текущая сцена / план вечера**. Портретная: переключаемые вкладки «Группа / Сцена / Подготовка / Журнал».

Тап на карточку персонажа показывает компактное меню:

- Назначить ранение или восстановление.
- Дать/забрать предмет.
- **Назначить эффект** (тип, публичное имя, скрытая причина, сила штрафа, длительность, только кому виден).
- Показать/изменить характеристики, согласовать изменение.
- Снять эффект или **откатить последнее действие**.

Все действия записываются с `actor_id`, временем, предыдущим и новым состоянием. Скрытые заметки никогда не отправлять клиентам игроков.

## Эффекты — первая механика для реализации

Пример записи:

```json
{
  "id": "uuid",
  "characterId": "uuid",
  "kind": "mental",
  "label": "Дезориентация",
  "publicDescription": "Сложнее ориентироваться в пространстве",
  "gmPrivateNote": "Причина пока не установлена",
  "visibility": "owner",
  "modifierDice": -1,
  "duration": { "mode": "until_gm_removes" },
  "source": "GM",
  "active": true,
  "createdBy": "gm-user-id",
  "createdAt": "ISO-8601"
}
```

Публичное и секретное хранить раздельно при формировании API-ответа, а не только скрывать CSS. Произвольные модификаторы должны соответствовать решению мастера, приложение не трактует правила самостоятельно.

## Как ускорить без переписывания

1. **Один сервер, одна модель данных.** За основу взять `server/index.js` (роли, кампания, SSE). Локальный Cloudflare PWA перестать развивать параллельно. Для доступа через Cloudflare можно опубликовать существующий Node-сервер через Cloudflare Tunnel и HTTPS, затем заменить frontend по экранам. Если нужна инфраструктура целиком на Workers — это отдельная миграция на D1, не мешать с текущими правками UX.
2. **Реальный MVP:** игровые экраны телефона и планшета, просмотр персонажей GM, эффект → изменения → журнал → отмена. Сначала пройти полный e2e-сценарий с двумя аккаунтами.
3. **Облегчить интерфейс:** никаких обязательных фоновых изображений; один нормальный шрифт для полей, один акцент, маленькие SVG; таб-навигация, большие сенсорные области (не менее 44 px).
4. **Потом** добавить план вечера, заметки GM и безопасный импорт Obsidian.
5. **Позже** APK/PWA-полировка, офлайн-очередь и разрешение конфликтов.

## Критерии приёмки MVP

- Телефон: от открытия приложения до броска ≤3 осмысленных нажатий (при заданных параметрах проверки — одно).
- Планшет: от выбора игрока до назначения эффекта ≤3 действия.
- Изменение персонажа мастером видно игроку без ручного обновления.
- Игрок не видит чужих закрытых данных и секретов мастера даже при прямом HTTP-запросе.
- Все эффекты/изменения можно удалить или отменить; журнал сохраняет историю.
- Работает на Android 360–430 px и планшете 768–1280 px, альбом/портрет.
- Логика d10 и 9 атрибутов Resident не заменяется правилами D&D, WoD V5 или LANCER.
- В споре 18/21 очко выбор определяется настройкой мастера.
