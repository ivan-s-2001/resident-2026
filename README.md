# Resident 2026 · Field Companion

**Приложение-дополнение для очных НРИ-сессий**, а не виртуальный стол: участники сидят рядом, общаются и используют только физические d10. На телефоне или ПК у каждого свой интерактивный чарник; мастер ведёт сцену, инициативу и заметки. Адаптировано для desktop и телефона; устанавливается как PWA на Android и Windows.

**Статус:** первая альфа. Нужен Node.js сервер. GitHub Pages не подходит — для аккаунтов и синхронизации необходим backend. Отдельный APK пока не создан.

## Единое приложение GM + игроки (Cloudflare)

**Открыть:** https://resident-2026-sheet.ivan-s-2001.workers.dev/

Это единое приложение для очной кампании: игроки открывают чарник с Android, мастер управляет персонажами с планшета. Все проверки выполняются физическими d10; генератора бросков нет.

- **GM:** видит всю группу, создаёт персонажей игрокам, исправляет любые чарники, отмечает физический и психологический урон, лечит, назначает открытые и скрытые эффекты, управляет приглашениями, готовит вечер с блоками «сцена / заметка / задача / раздел», публикует сцену игрокам и просматривает журнал.
- **Игрок:** видит собственные чарники, здоровье, эффекты, правит навыки, характеристики, вещи и заметки. Не может самостоятельно менять серверные повреждения и эффекты мастера. Сведения о скрытых эффектах не передаются его аккаунту.
- **Синхронизация:** Cloudflare Workers + D1, опрос изменений при активной вкладке примерно каждые 4 секунды. Клиент без сети может оставаться открыт, но новые правки требуют подключения.
- **Авторизация:** один мастер и игроки по его приглашению. Пароли хешируются PBKDF2; сессии находятся в HttpOnly Secure cookie. Для начальной настройки используется отдельный секретный код, не опубликованный в репозитории.
- **Миграция:** старый локальный чарник по ключу `resident2026-paper-v1` сохраняется в браузере. После входа можно вручную перенести его в аккаунт. Перед очисткой кэша желательно сохранить оригинальный JSON.
- **Фото:** можно добавить с телефона; изображение сжимается перед передачей в D1 и доступно только владельцу и мастеру.

Исходники нового Cloudflare-приложения: [API](cloudflare/team-api.js), [интерфейс](cloudflare/team-page.js), [схема D1](cloudflare/team-schema.sql). Проверки: `server/team-worker.test.js`.

### Минимум действий за игровым столом

- **Игрок:** в одном обзоре видит здоровье, активные состояния, основные навыки и снаряжение. Кнопка **«Заметки»** открывает поле с фокусом для немедленного ввода. Все текстовые поля, параметры, навыки и предметы сохраняются автоматически (задержка 550 мс), без кнопки «Сохранить».
- **Мастер на планшете:** список персонажей и выбранный лист расположены рядом. Ранение, лечение или один из типовых эффектов (стресс, контузия, заражение) назначается одним нажатием. Произвольные или скрытые воздействия находятся в дополнительной сворачиваемой форме.
- **Офлайн:** прежние значения, уже показанные на экране, не исчезают, но подтверждение изменений требует сети. При ошибке запись остаётся в форме, появляется действие для повторной отправки. Изменения **не хранятся в полноценной офлайн-очереди**.
- **Демонстрации без регистрации:** [игрок на телефоне](https://resident-2026-sheet.ivan-s-2001.workers.dev/?demo=player) и [GM на планшете](https://resident-2026-sheet.ivan-s-2001.workers.dev/?demo=gm). Это **изолированные, непостоянные примеры**: изменения в демо не затрагивают настоящую кампанию и исчезают после обновления страницы.
- **Кубики:** приложение не моделирует броски и не заменяет действия за игровым столом; оно служит электронной заменой бумаги.

**Важное различие:** прежний Node.js-сервер с MariaDB/JSON и новая Cloudflare D1 база не имеют общей учётной базы. В облачной версии мастер и игроки регистрируются заново. Данные старого браузерного листа переносятся по кнопке, но существующая локальная или Node.js-кампания автоматически не импортируется.

**Архивная версия:** прежний автономный PDF-чарник сохранён в [cloudflare/resident-paper-worker.js](cloudflare/resident-paper-worker.js) как исторический прототип; это больше не основной интерфейс.

## Возможности

- Аккаунты с логином и паролем, HttpOnly-cookie, salted scrypt-хеши паролей.
- **Одна общая кампания на всё приложение.** Первый зарегистрированный участник инициализирует её и становится мастером. Остальные входят по коду приглашения. Нет списка кампаний и переключения между ними. Дополнительные мастера назначаются создателем.
- Онлайн-чарник: 9 атрибутов, распределение 5/4/3, навыки, способности, инвентарь, биография, личные записи.
- Физические и психологические ранения: тупые и летальные, автоматический расчёт максимума здоровья.
- Все броски выполняются физическими d10. В приложении нет симулятора кубиков; правила трактовки результатов доступны как справочник.
- Сложность задаёт мастер для сцены.
- Синхронизация событий, чарников, назначенных мастером эффектов и ранений, сцены и инициативы через Server-Sent Events.
- Пульт мастера: сцена, сложность, закрытые заметки, скрытые NPC, инициатива, приглашения, роли.
- Mobile-first интерфейс, PWA и краткий справочник правил без спойлеров.

## Запуск

Требуется Node.js **22+**. Дополнительных npm-зависимостей нет.

~~~bash
git clone https://github.com/ivan-s-2001/resident-2026.git
cd resident-2026
npm start
~~~

Откройте http://localhost:3000. Зарегистрируйтесь: **первый пользователь** один раз создаёт единую кампанию, получает права мастера и приглашает остальных по коду. Все последующие игроки после входа сразу попадают в свой чарник; если их ещё не пригласили, они видят экран ввода кода. Создать вторую кампанию нельзя, это запрещено сервером.

Разработка: npm run dev. Проверки: npm run check && npm test.

## Docker + HTTPS

~~~bash
docker build -t resident-2026 .
docker run -d --name resident-2026 --restart unless-stopped \
  -p 127.0.0.1:3000:3000 -v resident26-data:/app/data resident-2026
~~~

Для доступа с Android или другого ПК используйте reverse proxy с HTTPS (Caddy или Nginx с TLS).

Пример Caddyfile:

~~~caddyfile
resident.example.com {
  reverse_proxy 127.0.0.1:3000
}
~~~

Dockerfile выставляет NODE_ENV=production. Не размещайте сервер в интернете через обычный HTTP. Нужны резервные копии Docker-тома /app/data.

Приложение пока хранит аккаунты, чарники и одну кампанию **в одном JSON-файле**. Это MVP для одной инстанции сервера и небольшой группы. Для production с большим количеством пользователей перейдите на PostgreSQL.

## Права доступа и материалы хроники

- Все API проверяют аккаунт и участие в кампании.
- Заметки мастера и скрытые NPC защищены на сервере, не только спрятаны в интерфейсе.
- Личные заметки персонажа читают владелец и мастер.
- В публичный репозиторий **не загружены** сюжетные секреты из исходного архива.
- Для публичной эксплуатации рекомендуется регистрация по приглашениям, восстановление доступа, прокси-rate-limit и база данных с резервным копированием.

## Быстрый старт за столом

1. Мастер инициализирует единую кампанию, приглашает игроков, задаёт сцену и сложность.
2. Игрок регистрируется, вводит код приглашения и создаёт оперативника. При следующих входах приложение открывает эту кампанию сразу.
3. В чарнике заполняет атрибуты, навыки, снаряжение, отмечает ранения.
4. Во время сессии игрок использует физические кубики. Чарник показывает характеристики, здоровье, навыки, снаряжение и полученные от мастера эффекты.
5. С Android-планшета мастер просматривает группу, назначает и снимает эффекты, корректирует здоровье, планирует вечер, управляет сценами и закрытыми записями.

## Использованные правила

Из предоставленного Obsidian-архива «Резидент 2026»: создание персонажа, атрибуты, навыки, броски d10, здоровье, боевые действия. Справочник содержит сокращённые игровые правила без материалов хроники.

В основных правилах навыки и предметы получают общий бюджет 21 очко, хотя старый PDF-чарник использует 18. За основу принят основной текст. Стоимость способностей задаёт мастер.
